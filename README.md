# Бот отчётов о билетах: QTickets → Телеграм

Бот присылает в телеграм-чаты сообщения о том, сколько билетов куплено на
сегодняшние сеансы ваших мероприятий в QTickets. Его можно добавить в любое
число чатов, в каждом чате настроить свой набор мероприятий, расписание
уведомлений и часовой пояс. Всё управление — кнопками в меню.

Формат сообщений (название спектакля — жирным, берётся из QTickets):

    **С любовью, Эрнест (Прм)**
    На сегодня куплено билетов:
    19:00 — 1
    21:00 — 3

Показываются только сеансы, на которые уже есть зрители. Если продаж нет
совсем — одна строка:

    **С любовью, Эрнест (Прм)**
    На сегодня куплено билетов: 0

На каждый спектакль бот присылает **отдельное** сообщение — даже если
время отправки у них совпало. Так на заблокированном экране телефона в
уведомлении от Телеграма видно название именно того спектакля, о котором
речь: push показывает начало текста, а начинается он с названия.

Чтобы название было видно на заблокированном экране, в Телеграме должен
быть включён показ текста в уведомлениях: Настройки → Уведомления и звук →
«Показывать текст сообщения» (в разных версиях пункт называется чуть
по-разному). И чат, конечно, не должен быть в беззвучном режиме.

---

## Как бот устроен (в двух словах)

* Бот работает по принципу «длинного опроса»: он сам регулярно спрашивает
  Телеграм, нет ли новых сообщений. Поэтому серверу **не нужны** ни свой
  домен, ни сертификаты — достаточно выхода в интернет.
* Все настройки хранятся в одном файле-базе `data.db` рядом с кодом.
  Скопировали этот файл — сделали резервную копию всех настроек.
* Раз в 20 секунд бот сверяется с расписаниями: если в каком-то чате
  наступила нужная минута — собирает данные из QTickets и отправляет отчёт.
  Каждая отправка записывается в журнал, поэтому дублей не бывает даже
  после перезапуска.
* Управлять ботом могут только люди из списка владельцев. Если бота добавит
  в чат посторонний, бот вежливо откажется и сам выйдет.

## Что понадобится

1. **Токен телеграм-бота** — ключ, который выдаёт @BotFather.
2. **Токен QTickets** — ключ доступа к вашему кабинету QTickets.
3. **Ваш числовой Телеграм-ID** — чтобы бот слушался только вас.
4. Аккаунт на github.com и сервер FirstVDS с Ubuntu.

### Шаг 1. Создать бота у @BotFather

1. Откройте в Телеграме @BotFather → команда `/newbot`.
2. Придумайте имя (например, «Эрнест Билеты») и логин бота
   (должен оканчиваться на `bot`, например `ErnestTicketsNewBot`).
3. BotFather пришлёт **токен** — длинную строку вида `1234567890:AA...`.
   Сохраните её, никому не показывайте.

Если бот уже создан, а токен потерян или отозван, новый берётся так:
@BotFather → `/mybots` → выберите бота → **API Token**. Там же есть кнопка
**Revoke current token** — она выпускает новый токен взамен старого
(старый сразу перестаёт работать; это же нужно сделать, если токен куда-то
утёк).

Больше в BotFather ничего менять не нужно. В частности, «режим
конфиденциальности» (privacy mode) можно не трогать: единственный случай,
когда бот ждёт от вас текст (ввод ID мероприятия вручную), сделан через
«ответ на сообщение бота» — такие сообщения Телеграм доставляет боту всегда.

### Шаг 2. Получить токен QTickets

В личном кабинете QTickets откройте раздел **Настройки → Основное** и
пролистайте в самый низ — там формируется токен для API
(страница: https://qtickets.app/organizers/myaccount). Если прежний токен
удалён или отозван, на этой же странице выпускается новый.
Это ключ ко всем данным о продажах — храните его как пароль.

### Шаг 3. Узнать свой Телеграм-ID

Напишите любое сообщение боту @userinfobot — он ответит числовым ID.
Если ботом будут пользоваться коллеги, соберите и их ID.

## Шаг 4. Положить код на GitHub (с Мака, в Терминале)

Так код будет лежать в одном месте, а обновлять бота на сервере можно
будет одной командой.

**4.1. Проверьте, что на Маке есть git.** Откройте Терминал
(Программы → Утилиты → Терминал) и введите:

    git --version

Если git не установлен, Мак сам предложит установить «Инструменты командной
строки» — согласитесь и дождитесь конца установки, потом повторите команду.

**4.2. Создайте пустой репозиторий на GitHub.** На github.com нажмите
**+ → New repository**. Имя: `ernest-bot`. Тип — **Public** (в коде нет
никаких ключей, а с публичным репозиторием сервер скачает код без пароля;
если хотите Private, см. примечание в конце этого шага). Галочки «Add a
README», «Add .gitignore», «Choose a license» — **не ставьте**, репозиторий
должен быть пустым. Нажмите **Create repository**.

**4.3. Отправьте код.** Распакуйте архив `ernest-tickets-bot.zip` (двойной
клик), затем в Терминале выполните по очереди — путь подставьте свой, если
папка не в «Загрузках»:

    cd ~/Downloads/ernest-bot
    git init
    git add .
    git status

Команда `git status` покажет список файлов, которые уйдут на GitHub.
**Убедитесь, что в нём нет `.env` и `data.db`** — они исключены заранее
файлом `.gitignore`. Дальше:

    git commit -m "Первая версия бота"
    git branch -M main
    git remote add origin https://github.com/ВАШ_ЛОГИН/ernest-bot.git
    git push -u origin main

В последней команде git спросит логин и пароль. **Вместо пароля нужен
токен GitHub** (обычный пароль от аккаунта не подойдёт). Как его получить:
на github.com откройте **Settings → Developer settings → Personal access
tokens → Tokens (classic) → Generate new token (classic)**, задайте имя и
срок действия, отметьте область **repo** и нажмите **Generate token**.
Токен показывается один раз — сразу скопируйте его и вставьте в Терминал
как пароль. Терминал при вводе пароля ничего не показывает — это нормально,
просто вставьте и нажмите Enter. Мак сохранит токен в Связке ключей, так
что второй раз спрашивать не будет.

Обновите страницу репозитория на GitHub — файлы должны появиться.

*Примечание про Private.* Если репозиторий приватный, на сервере при
`git clone` тоже спросят логин и токен — введите те же. Всё остальное
одинаково.

## Шаг 5. Установка на сервер

Подключитесь к серверу по SSH (данные для входа — в письме FirstVDS или в
их панели). В том же Терминале на Маке:

    ssh root@ВАШ_IP_СЕРВЕРА

Дальше все команды выполняются уже на сервере:

    apt update
    apt install -y python3 python3-venv git

    git clone https://github.com/ВАШ_ЛОГИН/ernest-bot.git /opt/ernest-bot
    cd /opt/ernest-bot

    python3 -m venv venv
    venv/bin/pip install -r requirements.txt

    bash setup.sh

Скрипт задаст три вопроса — токен бота, токен QTickets и ваш Телеграм-ID —
и сам создаст из ответов файл `.env`, закрытый от посторонних. Вводите
значения по одному, каждое подтверждая клавишей Enter; правильность формата
скрипт проверит на месте и при ошибке просто переспросит.

Ключи при таком вводе **не попадают в историю команд Терминала** — в
отличие от случая, когда их вписывают прямо в командную строку. Проверить
результат: `cat .env` (должны быть три строки). Поменять ключи позже:
`nano .env` или снова `bash setup.sh`.

Пробный запуск:

    venv/bin/python main.py

Если всё в порядке, появится строка «Запущен бот @…». Напишите боту в
Телеграме `/start` — откроется меню. Остановите пробный запуск: `Ctrl+C`.
Если бот вместо этого перечислил ошибки настроек — он подскажет, какое поле
в `.env` исправить (`bash setup.sh` можно запустить заново).

## Шаг 6. Автозапуск (чтобы бот работал всегда)

Чтобы бот стартовал сам после перезагрузки сервера и поднимался после
сбоев, подключим его к системному диспетчеру служб (systemd):

    cp /opt/ernest-bot/ernest-bot.service /etc/systemd/system/
    systemctl daemon-reload
    systemctl enable --now ernest-bot

Проверка состояния и «живой» журнал работы:

    systemctl status ernest-bot
    journalctl -u ernest-bot -f        # выход — Ctrl+C

Полезное на будущее:

    systemctl restart ernest-bot       # перезапустить
    systemctl stop ernest-bot          # остановить

## Шаг 7. Настройка в Телеграме

1. **Добавьте бота в чат города** обычным участником. Права
   администратора ему в большинстве случаев не нужны — подробности ниже,
   в разделе «Какие права нужны боту в чате».
2. Отправьте в чат `/menu@ИМЯ_ВАШЕГО_БОТА`. Откроется меню с кнопками.
   В личной переписке с ботом всё работает так же — удобно для проверки.

### Какие права нужны боту в чате

Коротко: **обычно никаких — достаточно добавить бота участником.**
Он только пишет сообщения и показывает свои кнопки; читать переписку,
удалять сообщения, банить или приглашать людей ему не нужно.

Когда права всё-таки понадобятся:

* **Добавить бота в чат может только тот, у кого есть право приглашать
  участников.** В открытых (публичных) группах Телеграм разрешает
  добавлять ботов только администраторам.
* **Бота должен добавить владелец бота** — человек, чей Телеграм-ID указан
  в `OWNER_IDS`. Если бота добавит кто-то другой, бот напишет, что он
  личный, и сам выйдет из чата. Это защита от добавления в чужие чаты.
  Если добавлять будет сотрудник — сначала впишите его ID в `OWNER_IDS`
  на сервере (`nano .env`, затем `systemctl restart ernest-bot`).
* **Если в чате запрещено писать обычным участникам** (в настройках группы
  «Разрешения → Отправка сообщений» выключена — так делают в чатах-объявлениях),
  бот писать не сможет. Тогда сделайте его администратором: откройте
  участников чата → бот → «Изменить права» и **снимите все галочки, какие
  сможете снять**. Администратору право писать даётся автоматически,
  а всё остальное (удаление сообщений, блокировка, закрепление, приглашения,
  назначение админов) боту не нужно. Если Телеграм не даст сохранить совсем
  без прав, оставьте самое безобидное — например «Управление видеочатами».
* **Ничего не меняйте в «режиме конфиденциальности» (privacy mode).**
  Он включён по умолчанию, и так и надо: бот видит только команды,
  адресованные ему, и ответы на собственные сообщения. Переписку сотрудников
  он не читает.

Ещё две вещи, о которых полезно знать:

* **Команды в группе лучше писать с именем бота**: `/menu@ИМЯ_БОТА`,
  `/report@ИМЯ_БОТА`. Просто `/menu` в группе с несколькими ботами может
  до вашего бота не дойти — Телеграм отдаёт такие команды тому боту, который
  писал в чат последним. Проще всего не набирать вручную, а нажать на кнопку
  «/» рядом с полем ввода и выбрать команду из списка — Телеграм сам
  подставит имя бота.
* **Кнопки меню работают только у владельцев** из `OWNER_IDS`. Остальные
  участники чата уведомления получают, но настроить ничего не могут —
  на нажатие кнопки им придёт пояснение. Если сотрудники должны уметь
  запрашивать отчёт сами, добавьте их ID в `OWNER_IDS`.

### Что есть в меню

* **📊 Отчёт за сегодня** — отчёт по всем мероприятиям чата прямо сейчас
  (то же делает команда `/report`). Работает всегда, даже если
  авто-уведомления выключены.
* **🎭 Мероприятия** — список мероприятий чата. Нажав на мероприятие, можно
  задать ему своё расписание, вернуть общее или удалить его из чата
  (с подтверждением).
* **➕ Добавить мероприятие** — бот покажет список ваших мероприятий из
  QTickets (новые сверху), достаточно нажать на нужное. Либо кнопка
  «Ввести ID вручную»: бот попросит прислать числовой ID ответом на его
  сообщение и проверит его в QTickets.
* **⏰ Общее расписание** — дни недели и время для всех мероприятий чата
  сразу. Сначала отмечаете дни, затем час и минуты — всё кнопками.
* **🔕 / 🔔 Уведомления** — выключить или включить авто-уведомления в чате.
* **🌍 Часовой пояс** — пояс города, где идут показы. По нему бот понимает,
  что такое «сегодня», и когда отправлять сообщение. По умолчанию — Москва.

### Как работают расписания

* У чата есть **общее** расписание — действует на все его мероприятия.
* Любому мероприятию можно задать **своё** расписание — тогда общее для
  него не действует. Кнопка «Вернуть общее расписание» отменяет своё.
* На каждый спектакль приходит отдельное сообщение — чтобы его название
  попадало в уведомление на заблокированном экране.
* Перед строками с билетами всегда стоит название спектакля жирным. Оно
  берётся из QTickets **дословно**, вместе со скобками и пометками города:
  как записано в кабинете («С любовью, Эрнест (Прм)»), так и придёт.
  Переименовали мероприятие в кабинете — в следующем отчёте будет новое
  название, в боте ничего менять не нужно.

### Правила подсчёта

* Считаются только **оплаченные** билеты; возвращённые и удалённые
  не учитываются.
* Показываются только сеансы, на которые есть купленные билеты. Сеансы с
  нулём в сообщение не попадают.
* Когда спектаклей в чате несколько, сообщения идут по алфавиту названий.
  Отчёт по кнопке «Отчёт за сегодня» — наоборот, приходит одним сообщением
  со всеми спектаклями сразу: вы в этот момент и так смотрите в чат.
* Если продаж нет совсем — одна строка «На сегодня куплено билетов: 0».
* Если сегодня у мероприятия нет сеансов — «Сегодня сеансов нет».

## Обновление и резервная копия

**Обновление кода.** Правки удобно вносить на Маке и отправлять на GitHub:

    cd ~/Downloads/ernest-bot
    git add .
    git commit -m "Что изменилось"
    git push

А на сервере забрать их:

    cd /opt/ernest-bot
    git pull
    systemctl restart ernest-bot

Файлы `.env` и `data.db` при этом не трогаются — настройки сохраняются.

**Резервная копия** — это один файл `/opt/ernest-bot/data.db` (все чаты,
мероприятия и расписания). Скачать его на Мак можно так (команда
выполняется на **Маке**, не на сервере):

    scp root@ВАШ_IP_СЕРВЕРА:/opt/ernest-bot/data.db ~/Desktop/

## Частые вопросы

**Бот молчит, хотя расписание задано.** Проверьте по порядку: включены ли
уведомления в меню чата; тот ли день недели отмечен; тот ли часовой пояс
выбран (время считается по поясу чата, а не сервера); работает ли служба
(`systemctl status ernest-bot`). Журнал ошибок: `journalctl -u ernest-bot -e`.

**Сервер был выключен в момент отправки.** Пропущенные уведомления задним
числом не досылаются — нажмите «Отчёт за сегодня».

**В списке «Добавить мероприятие» нет нужного.** Список показывает до 100
последних мероприятий из QTickets. Если нужного нет — добавьте его по ID
вручную (ID виден в адресной строке страницы мероприятия в кабинете).

**Группу превратили в супергруппу.** Телеграм меняет при этом внутренний
номер чата — бот переносит настройки автоматически.

**Бота случайно удалили из чата.** Настройки чата не стираются, только
выключаются уведомления. Верните бота и включите уведомления в меню.

**В отчёте строка с ⚠️ и ошибкой QTickets.** QTickets не ответил или не
принял токен — текст ошибки подскажет причину. Сбой по одному мероприятию
не мешает отчётам по остальным.

**Ошибка про часовые пояса (ZoneInfo/tzdata) при запуске.** Выполните
`apt install -y tzdata` и перезапустите бота.

**`git push` ругается на права доступа.** Скорее всего вместо токена введён
пароль от аккаунта. Создайте токен (шаг 4.3) и повторите; если Мак
запомнил неверный пароль, удалите запись «github.com» в программе
«Связка ключей».

## Безопасность

* Управлять ботом могут только ID из `OWNER_IDS`. Остальным бот отвечает,
  что доступ ограничен.
* Если бота добавит в чужой чат посторонний, бот сам выйдет из такого чата.
* Файл `.env` с ключами создаётся скриптом `setup.sh` прямо на сервере и
  исключён из репозитория файлом `.gitignore` — на GitHub он не попадёт.
  Не пересылайте его и не выкладывайте.
* Не вписывайте ключи прямо в командную строку и не пересылайте их в
  переписках: всё, что набрано в Терминале, остаётся в истории команд.
  Скрипт `setup.sh` этого избегает.
* Если токен QTickets или токен бота всё же куда-то утёк — выпустите новый
  (в QTickets — на той же странице настроек, в Телеграме — командой
  `/revoke` у @BotFather) и обновите `.env` на сервере.
