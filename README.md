# Бот отчётов о билетах: QTickets → Телеграм

Бот присылает в телеграм-чаты сообщения о том, сколько билетов куплено на
сегодняшние сеансы ваших мероприятий в QTickets. Его можно добавить в любое
число чатов, в каждом чате настроить свой набор мероприятий, расписание
уведомлений и часовой пояс. Управление — кнопками в меню; время отправки
пишется текстом.

Формат сообщений (название спектакля — жирным, берётся из QTickets):

    **С любовью, Эрнест**
    На сегодня куплено билетов:
    19:00 — 1
    21:00 — 3

Показываются только сеансы, на которые уже есть зрители. Если продаж нет
совсем — одна строка:

    **С любовью, Эрнест**
    На сегодня куплено билетов: 0

На каждый спектакль бот присылает **отдельное** сообщение — даже если
время отправки у них совпало. Так на заблокированном экране телефона в
уведомлении от Телеграма видно название именно того спектакля, о котором
речь: push показывает начало текста, а начинается он с названия.

Чтобы название было видно на заблокированном экране, в Телеграме должен
быть включён показ текста в уведомлениях: Настройки → Уведомления и звук →
«Показывать текст сообщения» (в разных версиях пункт называется чуть
по-разному). И чат, конечно, не должен быть в беззвучном режиме.

---

## Как бот устроен (в двух словах)

* Бот работает по принципу «длинного опроса»: он сам регулярно спрашивает
  Телеграм, нет ли новых сообщений. Поэтому серверу **не нужны** ни свой
  домен, ни сертификаты — достаточно выхода в интернет.
* Все настройки хранятся в одном файле-базе `data.db` рядом с кодом.
  Скопировали этот файл — сделали резервную копию всех настроек.
* Раз в 20 секунд бот сверяется с расписаниями: если в каком-то чате
  наступила нужная минута — собирает данные из QTickets и отправляет отчёт.
  Каждая отправка записывается в журнал, поэтому дублей не бывает даже
  после перезапуска.
* Управлять ботом могут только люди из списка владельцев. Если бота добавит
  в чат посторонний, бот вежливо откажется и сам выйдет.

## Что понадобится

1. **Токен телеграм-бота** — ключ, который выдаёт @BotFather.
2. **Токен QTickets** — ключ доступа к вашему кабинету QTickets.
3. **Ваш числовой Телеграм-ID** — чтобы бот слушался только вас.
4. Аккаунт на github.com и сервер FirstVDS с Ubuntu.

### Шаг 1. Получить токен телеграм-бота

**Если бот ещё не создан:** откройте в Телеграме @BotFather → команда
`/newbot` → придумайте имя (например «PROCESS Билеты») и логин, который
оканчивается на `bot`. BotFather пришлёт **токен** — длинную строку вида
`1234567890:AA...`.

**Если бот уже создан, а токен нужно выпустить заново** (например, старый
где-то засветился): @BotFather → `/mybots` → выберите своего бота →
**API Token** → **Revoke current token**. BotFather выдаст новый токен, а
старый сразу перестанет работать.

Токен — это пароль от бота. Сохраните его в надёжном месте и никому не
показывайте.

Если бот уже создан, а токен потерян или отозван, новый берётся так:
@BotFather → `/mybots` → выберите бота → **API Token**. Там же есть кнопка
**Revoke current token** — она выпускает новый токен взамен старого
(старый сразу перестаёт работать; это же нужно сделать, если токен куда-то
утёк).

Больше в BotFather ничего менять не нужно. В частности, «режим
конфиденциальности» (privacy mode) можно не трогать: единственный случай,
когда бот ждёт от вас текст (ввод ID мероприятия вручную), сделан через
«ответ на сообщение бота» — такие сообщения Телеграм доставляет боту всегда.

### Шаг 2. Получить токен QTickets

В личном кабинете QTickets откройте раздел **Настройки → Основное** и
пролистайте в самый низ — там формируется токен для API
(страница: https://qtickets.app/organizers/myaccount). Если прежний токен
удалён или отозван, на этой же странице выпускается новый.
Это ключ ко всем данным о продажах — храните его как пароль.

### Шаг 3. Узнать свой Телеграм-ID

Напишите любое сообщение боту @userinfobot — он ответит числовым ID.
Если ботом будут пользоваться коллеги, соберите и их ID.

## Шаг 4. Положить код на GitHub (приложение GitHub на Маке)

Так код будет лежать в одном месте, а обновлять бота на сервере можно
будет одной командой. Ничего программировать не нужно — только несколько
нажатий в приложении.

**4.1. Распакуйте архив.** Двойной клик по `process-tickets-bot.zip` —
рядом появится папка `PROCESS-Tickets-bot`. Оставьте её там, где она есть
(обычно это «Загрузки»).

**4.2. Добавьте папку в приложение.** В GitHub Desktop: меню
**File → Add Local Repository → Choose…** и выберите папку `PROCESS-Tickets-bot`.

Приложение предупредит, что папка пока не является репозиторием. Это
нормально и так и должно быть: нажмите в тексте предупреждения ссылку
**create a repository**.

**4.3. Создайте репозиторий.** В открывшемся окне:

* **Name** — `PROCESS-Tickets-bot`
* **Initialize this repository with a README** — галочку **не ставить**
  (файл README уже лежит в папке)
* **Git Ignore** — оставить **None** (файл `.gitignore` тоже уже есть,
  именно он не пустит ключи на GitHub)
* нажмите **Create repository**

**4.4. Опубликуйте.** В верхней панели нажмите **Publish repository**.
В открывшемся окне **снимите галочку «Keep this code private»** — тогда
сервер скачает код без всяких паролей. Секретов в коде нет: ключи живут
только в файле `.env`, который создаётся уже на сервере и на GitHub не
попадает. Нажмите **Publish repository**.

Запомните адрес репозитория — он понадобится на следующем шаге:
`https://github.com/ВАШ_ЛОГИН/PROCESS-Tickets-bot`

*Если удобнее Терминал.* Тот же результат дают команды в папке с кодом:
`git init`, `git add .`, `git commit -m "Первая версия"`, `git branch -M main`,
`git remote add origin https://github.com/ВАШ_ЛОГИН/PROCESS-Tickets-bot.git`,
`git push -u origin main`. При отправке git попросит логин и вместо пароля —
токен GitHub (**Settings → Developer settings → Personal access tokens →
Tokens (classic)**, область `repo`).

## Шаг 5. Установка на сервер

Подключитесь к серверу по SSH (данные для входа — в письме FirstVDS или в
их панели). В том же Терминале на Маке:

    ssh root@ВАШ_IP_СЕРВЕРА

Дальше все команды выполняются уже на сервере:

    apt update
    apt install -y python3 python3-venv git

    git clone https://github.com/ВАШ_ЛОГИН/PROCESS-Tickets-bot.git /opt/PROCESS-Tickets-bot
    cd /opt/PROCESS-Tickets-bot

    python3 -m venv venv
    venv/bin/pip install -r requirements.txt

    bash setup.sh

Скрипт задаст три вопроса — токен бота, токен QTickets и ваш Телеграм-ID —
и сам создаст из ответов файл `.env`, закрытый от посторонних. Вводите
значения по одному, каждое подтверждая клавишей Enter; правильность формата
скрипт проверит на месте и при ошибке просто переспросит.

Ключи при таком вводе **не попадают в историю команд Терминала** — в
отличие от случая, когда их вписывают прямо в командную строку. Проверить
результат: `cat .env` (должны быть три строки). Поменять ключи позже:
`nano .env` или снова `bash setup.sh`.

Пробный запуск:

    venv/bin/python main.py

Если всё в порядке, появится строка «Запущен бот @…». Напишите боту в
Телеграме `/start` — откроется меню. Остановите пробный запуск: `Ctrl+C`.
Если бот вместо этого перечислил ошибки настроек — он подскажет, какое поле
в `.env` исправить (`bash setup.sh` можно запустить заново).

## Шаг 6. Автозапуск (чтобы бот работал всегда)

Чтобы бот стартовал сам после перезагрузки сервера и поднимался после
сбоев, подключим его к системному диспетчеру служб (systemd):

    cp /opt/PROCESS-Tickets-bot/process-tickets-bot.service /etc/systemd/system/
    systemctl daemon-reload
    systemctl enable --now process-tickets-bot

Проверка состояния и «живой» журнал работы:

    systemctl status process-tickets-bot
    journalctl -u process-tickets-bot -f        # выход — Ctrl+C

Полезное на будущее:

    systemctl restart process-tickets-bot       # перезапустить
    systemctl stop process-tickets-bot          # остановить

## Шаг 7. Настройка в Телеграме

1. **Добавьте бота в чат города** обычным участником. Права
   администратора ему в большинстве случаев не нужны — подробности ниже,
   в разделе «Какие права нужны боту в чате».
2. Отправьте в чат `/menu@ИМЯ_ВАШЕГО_БОТА`. Откроется меню с кнопками.
   В личной переписке с ботом всё работает так же — удобно для проверки.

### Какие права нужны боту в чате

Коротко: **обычно никаких — достаточно добавить бота участником.**
Он только пишет сообщения и показывает свои кнопки; читать переписку,
удалять сообщения, банить или приглашать людей ему не нужно.

Когда права всё-таки понадобятся:

* **Добавить бота в чат может только тот, у кого есть право приглашать
  участников.** В открытых (публичных) группах Телеграм разрешает
  добавлять ботов только администраторам.
* **Бота должен добавить владелец бота** — человек, чей Телеграм-ID указан
  в `OWNER_IDS`. Если бота добавит кто-то другой, бот напишет, что он
  личный, и сам выйдет из чата. Это защита от добавления в чужие чаты.
  Если добавлять будет сотрудник — сначала впишите его ID в `OWNER_IDS`
  на сервере (`nano .env`, затем `systemctl restart process-tickets-bot`).
* **Если в чате запрещено писать обычным участникам** (в настройках группы
  «Разрешения → Отправка сообщений» выключена — так делают в чатах-объявлениях),
  бот писать не сможет. Тогда сделайте его администратором: откройте
  участников чата → бот → «Изменить права» и **снимите все галочки, кроме
  «Удаление сообщений»** (о ней ниже). Право писать администратору даётся
  автоматически, а блокировка, закрепление, приглашения и назначение админов
  боту не нужны.
* **Право «Удаление сообщений»** нужно, только если вы хотите, чтобы бот
  убирал из чата и ваши команды (`/menu`, `/report`). Свои собственные
  сообщения — меню, экраны настройки, вопросы — он убирает без всяких прав.
  Выдаётся там же: участники чата → бот → «Изменить права» →
  «Удаление сообщений».
* **Ничего не меняйте в «режиме конфиденциальности» (privacy mode).**
  Он включён по умолчанию, и так и надо: бот видит только команды,
  адресованные ему, и ответы на собственные сообщения. Переписку сотрудников
  он не читает.

Ещё две вещи, о которых полезно знать:

* **Команды в группе лучше писать с именем бота**: `/menu@ИМЯ_БОТА`,
  `/report@ИМЯ_БОТА`. Просто `/menu` в группе с несколькими ботами может
  до вашего бота не дойти — Телеграм отдаёт такие команды тому боту, который
  писал в чат последним. Проще всего не набирать вручную, а нажать на кнопку
  «/» рядом с полем ввода и выбрать команду из списка — Телеграм сам
  подставит имя бота.
* **Кнопки меню работают только у владельцев** из `OWNER_IDS`. Остальные
  участники чата уведомления получают, но настроить ничего не могут —
  на нажатие кнопки им придёт пояснение. Если сотрудники должны уметь
  запрашивать отчёт сами, добавьте их ID в `OWNER_IDS`.

### Что есть в меню

* **📊 Отчёт за сегодня** — отчёт по всем мероприятиям чата прямо сейчас
  (то же делает команда `/report`). Работает всегда, даже если
  авто-уведомления выключены.
* **🎭 Мероприятия** — список мероприятий чата. Нажав на мероприятие, можно
  задать ему своё расписание, вернуть общее или удалить его из чата
  (с подтверждением).
* **➕ Добавить мероприятие** — бот покажет список ваших мероприятий из
  QTickets (новые сверху), достаточно нажать на нужное. Либо кнопка
  «Ввести ID вручную»: бот попросит прислать числовой ID ответом на его
  сообщение и проверит его в QTickets.
* **⏰ Общее расписание** — дни недели и время для всех мероприятий чата
  сразу. Дни отмечаются кнопками, время пишется текстом (см. раздел ниже).
* **🔕 / 🔔 Уведомления** — выключить или включить авто-уведомления в чате.
* **🌍 Часовой пояс** — пояс города, где идут показы. По нему бот понимает,
  что такое «сегодня», и когда отправлять сообщение. По умолчанию — Москва.
  При смене пояса время всех расписаний чата **пересчитывается**, чтобы
  отчёты приходили в тот же самый момент: 13:05 по Москве превращается
  в 15:05 по Екатеринбургу. Бот покажет, что и на что поменялось. Если
  пересчёт перевёл время через полночь, вместе с ним сдвигается и день
  недели. Повторного уведомления в день смены пояса не будет.

### Бот убирает за собой

Служебные сообщения бота не копятся в чате — он удаляет их сам:

* **Меню и экраны настройки** живут одним сообщением, которое меняется на
  месте. Оно исчезает через 5 минут после последнего нажатия — отсчёт
  начинается заново при каждой кнопке, так что настроить расписание никто
  не помешает. Можно убрать сразу кнопкой **✖️ Закрыть**.
* **Приветствие** при добавлении бота в чат исчезает через минуту.
* **Приглашение ввести ID** мероприятия убирается сразу после ввода.
* Если открыть меню заново, предыдущее удаляется — в чате всегда не больше
  одного меню.

Убираются и **ваши** команды (`/start`, `/menu`, `/report`, `/help`) вместе
с ответами на вопросы бота — чтобы в чате оставались только уведомления
о билетах.

В личной переписке это работает всегда. В групповом чате Телеграм разрешает
боту удалять чужие сообщения только если бот **администратор с правом
«Удаление сообщений»**. Выдать его: откройте список участников чата → бот →
«Изменить права» → включите «Удаление сообщений» (остальные галочки можно
не трогать). Без этого права ваши команды останутся в чате — ошибкой это
не считается, бот предупредит об этом строкой в меню.

**Отчёты о билетах не удаляются никогда** — ни присланные по расписанию,
ни запрошенные кнопкой «Отчёт за сегодня».

Права администратора для этого не нужны: свои сообщения бот вправе удалять
в любом чате. Чужие сообщения он не трогает — ваши команды `/menu` и
`/report` остаются в переписке (чтобы бот убирал и их, ему пришлось бы
выдать права администратора, а вместе с ними он начал бы получать все
сообщения чата — мы этого не делаем).

Очередь на уборку хранится в базе, а не в памяти, поэтому перезапуск бота
(при обновлении или перезагрузке сервера) её не теряет: после запуска
уборка продолжится сама.

Если бот не смог убрать ваши команды (нет права администратора), он честно
скажет об этом строкой в меню — гадать не придётся.

### Как задаётся расписание

Два шага.

**1. Дни недели — кнопками.** Откройте **⏰ Общее расписание** (или «Своё
расписание» в карточке мероприятия): семь кнопок с днями, отмеченные
помечены галочкой. Есть кнопка «Каждый день» (она же снимает все отметки).
Отметили — нажмите **«Далее: время →»**.

**2. Время — текстом.** Бот спросит одним вопросом: во сколько присылать
отчёт. Напишите ответом на его сообщение, например `18:32`. Никаких сеток
часов и минут — любое время задаётся за одно сообщение.

Время понимается свободно: `18:32`, `9:05`, `1930`, `в 19:00`, `18` (это
18:00). Заведомо неверное (`25:00`) бот не примет и попросит написать
заново.

В личной переписке просто напишите ответ обычным сообщением.

В групповом чате Телеграм по умолчанию не показывает боту чужую переписку —
поэтому там нужен **ответ** на сообщение бота. Обычно ничего делать не надо:
задавая вопрос, бот сам переводит ваше поле ввода в режим ответа, и текст
уходит куда нужно. Если поле не переключилось — свайп влево по сообщению
бота или «Ответить».

Хотите отвечать в группах обычными сообщениями — это можно включить:
@BotFather → `/mybots` → ваш бот → **Bot Settings → Group Privacy → Turn
off**. Тогда бот начнёт получать все сообщения чата (наш код чужие сообщения
игнорирует и никуда не сохраняет, но технически они до него доходят).
Решать вам; по умолчанию приватность включена.

То же касается кнопки **✍️ Ввести ID вручную**: бот спросит число, вы
отвечаете.

### Как работают расписания

* У чата есть **общее** расписание — действует на все его мероприятия.
* Любому мероприятию можно задать **своё** расписание — тогда общее для
  него не действует. Кнопка «Вернуть общее расписание» отменяет своё.
* На каждый спектакль приходит отдельное сообщение — чтобы его название
  попадало в уведомление на заблокированном экране.
* Перед строками с билетами всегда стоит название спектакля жирным. Оно
  берётся из QTickets и обновляется само: переименовали мероприятие
  в кабинете — в следующем отчёте будет новое название.
* Городская пометка в конце названия из уведомления убирается:
  «Леопарды Килиманджаро (Екб)» придут как «Леопарды Килиманджаро».
  Город и так понятен по названию чата. Работает для любого города —
  убирается сама скобка в конце, а не список заранее известных городов;
  скобки `(…)` и `[…]` равнозначны.
* Длинный подзаголовок в скобках при этом сохраняется: срезается только
  короткая пометка (до 24 знаков — в любое название города влезает
  с запасом). И если кроме скобки в названии ничего нет, оно остаётся
  как было.
* **В меню бота название показывается целиком, вместе с пометкой** — иначе
  одноимённые спектакли разных городов стало бы не различить при добавлении.

### Правила подсчёта

* Считаются только **оплаченные** билеты; возвращённые и удалённые
  не учитываются.
* Показываются только сеансы, на которые есть купленные билеты. Сеансы с
  нулём в сообщение не попадают.
* Когда спектаклей в чате несколько, сообщения идут по алфавиту названий.
  Отчёт по кнопке «Отчёт за сегодня» — наоборот, приходит одним сообщением
  со всеми спектаклями сразу: вы в этот момент и так смотрите в чат.
* Если продаж нет совсем — одна строка «На сегодня куплено билетов: 0».
* Если сегодня у мероприятия нет сеансов — «Сегодня сеансов нет». Отменённые
  (выключенные) и удалённые сеансы за сеансы не считаются.
* Разница между «Сегодня сеансов нет» и «куплено билетов: 0» важная:
  первое значит, что показа сегодня вообще нет; второе — показ есть,
  но билетов на него пока не купили.

## Про имена: что с чем связано

Имя проекта нигде не «зашито» в код — переименовать можно спокойно.
Значение имеют только три места, и они не обязаны совпадать:

* **Имя репозитория на GitHub** (`PROCESS-Tickets-bot`) — просто название
  страницы. Влияет лишь на адрес для `git clone`.
* **Имя папки на сервере** (`/opt/PROCESS-Tickets-bot`) — набирайте его
  ровно с такими же заглавными буквами: в Линуксе `PROCESS` и `process` —
  разные папки. Чтобы не ошибаться, наберите `cd /opt/PRO` и нажмите Tab —
  Терминал допишет остальное сам. Это имя — то, что вы
  набираете в командах. Записано в файле `process-tickets-bot.service`
  в двух строках: `WorkingDirectory` и `ExecStart`. Меняете папку —
  поменяйте и их.
* **Имя службы** — это имя файла `.service` в `/etc/systemd/system/`.
  Именно оно подставляется в `systemctl` и `journalctl`.

В самих файлах с кодом (`main.py`, `db.py` и остальных) имени проекта нет,
поэтому переименование их не затрагивает. Логин бота в Телеграме к имени
папки тоже никак не привязан.

## Если цифры в отчёте выглядят странно

В комплекте есть проверочный скрипт: он ничего не меняет, только показывает,
какие сеансы QTickets отдаёт по мероприятию и какие из них бот считает
сегодняшними.

    cd /opt/PROCESS-Tickets-bot
    venv/bin/python check_event.py 186377

Число в конце — ID мероприятия (он виден в карточке мероприятия в меню бота).
Вторым словом можно задать часовой пояс, если он отличается от
екатеринбургского:

    venv/bin/python check_event.py 186377 Europe/Moscow

В выводе для каждого сеанса видно: дату из QTickets, ту же дату по поясу
чата, признаки «выключен» и «удалён», и пометку, считает ли бот этот сеанс
сегодняшним.

## Обновление и резервная копия

**Обновление кода.** Правки вносятся на Маке и отправляются на GitHub —
в приложении GitHub это два нажатия: слева внизу впишите короткое описание
правки и нажмите **Commit to main**, затем вверху — **Push origin**.

А на сервере забрать обновление:

    cd /opt/PROCESS-Tickets-bot
    git pull
    systemctl restart process-tickets-bot

Файлы `.env` и `data.db` при этом не трогаются — настройки сохраняются.

**Резервная копия** — это один файл `/opt/PROCESS-Tickets-bot/data.db` (все чаты,
мероприятия и расписания). Скачать его на Мак можно так (команда
выполняется на **Маке**, не на сервере):

    scp root@ВАШ_IP_СЕРВЕРА:/opt/PROCESS-Tickets-bot/data.db ~/Desktop/

## Частые вопросы

**Бот молчит, хотя расписание задано.** Проверьте по порядку: включены ли
уведомления в меню чата; тот ли день недели отмечен; тот ли часовой пояс
выбран (время считается по поясу чата, а не сервера); работает ли служба
(`systemctl status process-tickets-bot`). Журнал ошибок: `journalctl -u process-tickets-bot -e`.

**Сервер был выключен в момент отправки.** Пропущенные уведомления задним
числом не досылаются — нажмите «Отчёт за сегодня».

**В списке «Добавить мероприятие» нет нужного.** Список показывает до 100
последних мероприятий из QTickets. Если нужного нет — добавьте его по ID
вручную (ID виден в адресной строке страницы мероприятия в кабинете).

**Группу превратили в супергруппу.** Телеграм меняет при этом внутренний
номер чата — бот переносит настройки автоматически.

**Бота случайно удалили из чата.** Настройки чата не стираются, только
выключаются уведомления. Верните бота и включите уведомления в меню.

**В отчёте строка с ⚠️ и ошибкой QTickets.** QTickets не ответил или не
принял токен — текст ошибки подскажет причину. Сбой по одному мероприятию
не мешает отчётам по остальным.

**Ошибка про часовые пояса (ZoneInfo/tzdata) при запуске.** Выполните
`apt install -y tzdata` и перезапустите бота.

**Ошибка `TypeError: 'type' object is not subscriptable` при запуске.**
На сервере слишком старый Python — нужен 3.9 или новее. Проверить:
`python3 --version`. На Ubuntu 20.04 (там по умолчанию 3.8) нужный Python
есть в родных репозиториях системы:

    apt install -y python3.9 python3.9-venv
    cd /opt/PROCESS-Tickets-bot
    rm -rf venv
    python3.9 -m venv venv
    venv/bin/pip install -r requirements.txt

Файл `.env` с ключами при этом не трогается — вводить их заново не нужно.

**`git push` ругается на права доступа.** Скорее всего вместо токена введён
пароль от аккаунта. Создайте токен (шаг 4.3) и повторите; если Мак
запомнил неверный пароль, удалите запись «github.com» в программе
«Связка ключей».

## Безопасность

* Управлять ботом могут только ID из `OWNER_IDS`. Остальным бот отвечает,
  что доступ ограничен.
* Если бота добавит в чужой чат посторонний, бот сам выйдет из такого чата.
* Файл `.env` с ключами создаётся скриптом `setup.sh` прямо на сервере и
  исключён из репозитория файлом `.gitignore` — на GitHub он не попадёт.
  Не пересылайте его и не выкладывайте.
* Не вписывайте ключи прямо в командную строку и не пересылайте их в
  переписках: всё, что набрано в Терминале, остаётся в истории команд.
  Скрипт `setup.sh` этого избегает.
* Если токен QTickets или токен бота всё же куда-то утёк — выпустите новый
  (в QTickets — на той же странице настроек, в Телеграме — командой
  `/revoke` у @BotFather) и обновите `.env` на сервере.
